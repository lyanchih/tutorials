第 1 章為什麼需要「浮點數」？

假設你只有 8 個格子可以寫數字，而且小數點的位置固定在中間（這叫定點數）：

0012.3400→ 12.34 ✅ 沒問題
9999.9999→ 最大只能到 9999.9999 😢
0000.0000→ 0.00000123 直接變成 0 😭

範圍和精度只能二選一。科學家早就有解法——科學記號：

6.02 × 1023

有效數字負責「精確度」，指數負責「大小（範圍）」。小數點的位置跟著指數浮動，所以叫做浮點數 (floating point)！

電腦用的是二進位，所以浮點數其實就是「二進位的科學記號」：

± 1.xxxxx₂ × 2指數

拖動滑桿改變指數，看小數點如何左右移動。同樣的 1011 四個位元，可以變成很大或很小的數！

💡 二進位小數怎麼讀？ 小數點右邊的位數依序代表 ½、¼、⅛、1/16……。例如 0.101₂ = ½ + ⅛ = 0.625。

第 2 章三兄弟的身體構造

IEEE 754 把一串位元切成三段：

S 符號位 (Sign)

1 個位元。0 = 正、1 = 負。

E 指數 (Exponent)

決定數字在「哪一層樓」——也就是大小範圍。

F 尾數 (Fraction / Mantissa)

決定在那一層樓的「哪個房間」——也就是精確位置。

值 = (−1)S × 1.F₂ × 2E − 偏差值

🤔 兩個聰明的小設計

① 隱藏的 1（hidden bit）

二進位科學記號正規化後，小數點前面一定是 1（不像十進位可能是 1~9）。既然一定是 1，就不用存！

所以單精度明明只存 23 位尾數，卻有 24 位精度，白賺一位 🎁。

1.0101 × 23 → 只存 0101…

② 偏差值（bias）

指數可以是負的（例如 2−3），但指數欄位存的是無號整數。解法：存「實際指數 + 偏差值」。

偏差值 = 2(指數位數−1) − 1 → 半精度 15、單精度 127、雙精度 1023。

好處：正數的位元直接當整數比大小，順序就和數值大小一致！

🎚️ 偏差值轉換器

🏢 大樓比喻：把所有正數想成一棟大樓。

  • 指數 = 樓層。第 E 層包含 [2E, 2E+1) 這段範圍。
  • 尾數 = 房號。每層都被平均切成 2尾數位數 個房間（半精度 1024 間、單精度約 838 萬間）。
  • 樓層越高，範圍越寬，但房間數一樣 → 房間越大，越不精確。這就是浮點數「越大越粗糙」的原因！

👀 你觀察到了嗎？

  1. 點在 0 附近很密，越往右越稀疏——每過一個 2 的次方，間距就翻倍。
  2. 每一「層」（同一顏色的區段）點的數量都一樣多。
  3. 最左邊那些灰色點是次正規數，它們把 0 和最小的正規化數之間均勻填滿（第 6 章會講）。
  4. 試試把尾數位數調大：每層的點變多 → 精度提高。把指數位數調大：層數變多 → 範圍變大。

半精度 / 單精度 / 雙精度，其實就是「指數幾位、尾數幾位」的不同取捨而已！

    第 6 章特殊值動物園 🦁

    指數欄位的全 0 和全 1 這兩個極端值被保留下來，用來表示特別的東西：

    種類指數欄位尾數欄位代表的值

    0️⃣ 正零與負零

    因為有符號位，所以有 +0 和 −0 兩種零！它們比較時相等（+0 == −0），但 1/+0 = +∞、1/−0 = −∞。

    🐜 次正規數 (subnormal)

    指數全 0 時，隱藏位元變成 0，指數固定為 1 − 偏差值：值 = ±0.F × 21−bias。

    它們填補 0 與最小正規化數之間的空隙，讓數字「慢慢」變成 0（稱為漸進式下溢），代價是精度逐漸變少。

    ♾️ 無限大

    指數全 1、尾數全 0。超出最大值（溢位）或 1/0 就會得到它。∞ 也能參與運算：∞ + 1 = ∞。

    👻 NaN（Not a Number）

    指數全 1、尾數非 0。代表「沒有意義的結果」，例如 0/0、∞ − ∞、√−1。

    NaN 不等於任何東西，包括它自己：NaN == NaN 是 false！

    🛝 下溢溜滑梯 & 🚀 溢位火箭

    從 1 開始，不斷 ÷2 或 ×2，觀察數字如何經過次正規區變成 0，或衝上 ∞。

    第 7 章精度、捨入與經典陷阱

    7.1 捨入規則：四捨五入？不完全是！

    尾數位數有限，放不下的位元必須捨入。IEEE 754 預設使用「最接近、平手取偶數」(round half to even)：

    • 比一半小 → 捨去
    • 比一半大 → 進位
    • 剛好一半 → 選最後一位是 0（偶數）的那個

    十進位類比（取到整數）：

    2.4 → 2　2.6 → 3
    2.5 → 2　3.5 → 4　4.5 → 4

    為什麼？傳統四捨五入遇到 .5 永遠往上，累積起來會偏大；取偶數則一半往上、一半往下，統計上不偏。

    🔬 捨入顯微鏡

    兩個相鄰的可表示數之間，其他數都必須「被吸」到其中一個。拖動滑桿，看看哪邊贏！

    📈 ULP 隨數值大小的變化

    7.4 停滯的計數器

    ⏱️ 把 0.1 加 N 次

    數學上答案是 N × 0.1。電腦每加一次就捨入一次，誤差會累積……甚至卡住！

    🎯 整數的極限

    精度是 p 位，代表 2p 以內的整數都能精確表示，超過之後就會開始「跳號」：

    • 半精度（p = 11）：2048 之後，2049 存不下（會變 2048）
    • 單精度（p = 24）：16,777,216 之後，16777217 存不下
    • 雙精度（p = 53）：9,007,199,254,740,992 之後存不下 → 這就是 JavaScript 的 Number.MAX_SAFE_INTEGER = 253 − 1！

    🧭 解碼口訣

    • 指數全 0：尾數 0 → ±0；否則次正規 0.F × 21−bias
    • 指數全 1：尾數 0 → ±∞；否則 NaN
    • 其他：1.F × 2E−bias

    ✍️ 編碼口訣

    轉二進位 → 正規化成 1.xxx × 2E → E + bias 存指數 → 小數點後取尾數（捨入取偶）→ 組合

    ⚠️ 程式設計師必知陷阱

    1. 不要用 == 比較浮點數 
    // ❌
0.1 + 0.2 === 0.3            // false

// ✅ 用容許誤差比較
Math.abs(a - b) <= 1e-9 * Math.max(1, Math.abs(a), Math.abs(b))
    2. 金額不要用浮點數

    0.1 元在二進位是無限循環小數。請用整數「分」來存，或用十進位型別（Python decimal、Java BigDecimal、C# decimal）。

    3. 大數加小數，小數會被「吃掉」 
    1e16 + 1 === 1e16            // true（雙精度）
// 加總很多數時，先排序由小加到大，或使用 Kahan 補償求和
    4. 檢查 NaN 要用專門函式 
    x === NaN          // 永遠 false ❌
Number.isNaN(x)    // ✅ JavaScript
math.isnan(x)      // ✅ Python
isnan(x)           // ✅ C / C++
    5. JavaScript 的整數不是無限大 
    9007199254740993           // 印出 9007199254740992
Number.MAX_SAFE_INTEGER    // 9007199254740991 = 2^53 − 1
// 更大的整數請用 BigInt：9007199254740993n
    6. 半精度的範圍很小

    半精度最大只有 65504，訓練神經網路時很容易溢位成 ∞，所以常搭配「損失縮放 (loss scaling)」，或改用指數位數與單精度相同的 bfloat16（1/8/7）。
