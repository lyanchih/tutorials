CHAPTER 0

為什麼要壓縮模型？

一句話重點 模型壓縮 = 用更少的位元、更少的參數或更小的架構，儘量保留原本的能力， 換來更小的記憶體、更快的推論、更低的耗電，以及能在便宜硬體上執行。

一個模型佔多少記憶體，只要一個公式就能估算：

權重大小（bytes）＝ 參數數量 × 每個參數的位元數8 例：Llama 3.1 8B 以 FP16（16 bits）儲存 → 8×10⁹ × 2 bytes ≈ 16 GB，一張 RTX 4090（24 GB）勉強放得下；改成 4 bits 只要約 4 GB。
實驗 0：模型放得進你的硬體嗎？
目標硬體

關鍵觀念：壓縮不只省空間，還會變快

大型語言模型（LLM）逐字生成時，每產生一個 token，都要把全部權重從記憶體讀一次。 這時 GPU 的運算單元多半在等資料，瓶頸是記憶體頻寬（memory-bound）。所以：

生成速度上限（token/s）≈ 記憶體頻寬（GB/s）權重大小（GB） 權重從 16 bits 變成 4 bits，要搬的資料變成 1/4，速度上限就約提高 4 倍。上面實驗中的 token/s 就是這樣估出來的（batch = 1 的理論上限）。

1. 一個 70 億（7B）參數的模型以 FP16 儲存，權重大約佔多少記憶體？

  1. 3.5 GB
  2. 7 GB
  3. 14 GB
  4. 28 GB

  1. 因為 4-bit 的乘法電路一定比較多
  2. 因為逐字生成的瓶頸是從記憶體搬運權重，資料量變成約 1/4
  3. 因為量化後參數數量變少了
  4. 其實不會變快，只會變小
batch 小的時候，LLM 解碼是 memory-bound：每個 token 都要讀過一次全部權重。位元數變少 → 要搬的 bytes 變少 → 更快。參數「數量」並沒有變。

數字在電腦裡怎麼存？

一句話重點 浮點數 = 符號 × 2指數 × 尾數。指數位元決定「範圍」（能表示多大多小）， 尾數位元決定「精細度」（相鄰兩個數字差多少）。位元總數固定時，兩者互相取捨。
值 = (−1)S × 2E − bias × (1 + M2尾數位數) ■ 符號 S：0 為正、1 為負 ■ 指數 E：以 bias 偏移表示正負次方 ■ 尾數 M：小數部分（前面隱含一個 1）。E 全為 0 時是「次正規數」，用來表示非常接近 0 的值。

⚠️ 常見誤解 「INT8 和 FP8 都是 8 bits，所以一樣」—— 不一樣。浮點數的刻度在 0 附近很密、越遠越疏（相對誤差固定）； 整數的刻度是均勻的（絕對誤差固定），而且只能表示整數，所以 INT 量化一定要搭配一個縮放係數 scale， 把真實數值的範圍對應到整數範圍。這就是下一章的主角。

CHAPTER 2

量化基礎：把實數對齊到刻度上

一句話重點 量化就是把連續的實數「四捨五入」到少數幾個等距刻度上，只儲存刻度的編號（小整數 q）和一個縮放係數 scale（以及可選的 zero-point）。 用的時候再乘回去：x̂ = s · (q − z)。

兩種最常見的線性量化

對稱量化（Symmetric）

s = max |x|2b−1 − 1，z = 0
q = clamp(round(x / s), −(2b−1−1), 2b−1−1)

刻度以 0 為中心左右對稱。計算簡單、硬體友善，權重（大致以 0 為中心）最常用。

非對稱量化（Asymmetric / Affine）

s = max − min2b − 1，z = round(−min / s)
q = clamp(round(x / s) + z, 0, 2b−1)

多一個 zero-point z，刻度貼合資料的實際範圍。適合分佈偏一邊的資料，例如 ReLU 之後的啟動值（全為正數）。

round = 四捨五入、clamp = 超出範圍就截到邊界。b = 位元數。

實驗 2：在數線上看量化（逐步計算）
量化方式

紅色列 = 四捨五入後超出整數範圍而被截斷（clamp）的值。

🔍 動手觀察
  1. 切換「對稱 / 非對稱」：這組資料大多是正數，對稱量化會把一半的刻度浪費在沒有資料的負數區。
  2. 把位元數從 3 調到 8：最大誤差永遠不超過 s/2，而 s 每多 1 bit 就約減半。
  3. 按「加入離群值 12」：一個極端值把範圍撐大 → s 變大 → 其他所有數值的誤差都變大。

粒度、離群值與截斷

真實模型有數百萬到數十億個權重，關鍵問題是：多少個權重共用一個 scale？

  • Per-tensor（整張量）：整個矩陣一個 scale。最省空間，但只要有一個離群值，整個矩陣都受害。
  • Per-channel（逐通道）：矩陣每一列（輸出通道）一個 scale。CNN 與 INT8 權重量化的標準做法。
  • Per-group（分組）：每 g 個連續權重（常見 g = 32、64、128）一個 scale。4-bit LLM 量化的主流做法。代價：scale 也要佔空間。
平均位元數 = b + scale 的位元數（常為 16）group size g 例：4-bit、g = 128、FP16 scale → 4 + 16/128 = 4.125 bits；g = 32 → 4.5 bits。所以「4-bit 模型」實際上通常略大於 4 bits/參數。

另一招是截斷（clipping）：故意把範圍設得比最大值小，犧牲少數離群值（截斷誤差變大），換取多數值的刻度變細（捨入誤差變小）。 PTQ 的「校準（calibration）」就是在找最佳的截斷範圍。

  4. 沒有離群值、per-tensor、3 bits 時，把截斷慢慢往左拉：SQNR 先上升（刻度變細）、過了某個點又下降（截掉太多）。找出最高點 —— 這就是校準在做的事。

CHAPTER 3

進階量化：PTQ、QAT 與大型語言模型

一句話重點 PTQ（訓練後量化）拿訓練好的模型直接量化，快速、不需訓練資料或只需少量校準資料； QAT（量化感知訓練）在訓練中模擬量化，讓模型學會適應誤差，準確度較好但成本高。 LLM 太大、很難重新訓練，因此發展出 GPTQ、AWQ、SmoothQuant 等聰明的 PTQ 方法。
PTQ 訓練後量化QAT 量化感知訓練
流程訓練好的模型 → 用幾百筆校準資料統計範圍 → 量化在訓練（或微調）時，前向傳播就使用量化後的權重
成本幾分鐘到幾小時，不需 GPU 叢集需要訓練資料與完整訓練流程
8-bit通常幾乎無損幾乎無損
4-bit 以下需要進階方法，否則掉很多通常明顯優於 PTQ
適用LLM、快速部署手機端 CNN、極低位元、對準確度要求高

QAT 的核心技巧：直通估計器（STE）

round() 是階梯函數，幾乎處處導數為 0，梯度傳不回去。STE 的做法很簡單粗暴：前向傳播用量化值，反向傳播假裝量化不存在。

前向：y = f( Q(w) )　　反向：∂L∂w ≈ ∂L∂Q(w) 也就是把 ∂Q(w)/∂w 當成 1。主權重 w 仍以高精度儲存並累積小幅更新，累積夠了就會跨到下一個刻度。第 7 章的實驗室就用這個方法做「微調」。

權重量化 vs. 權重＋啟動值量化

  • Weight-only（例：W4A16）：只量化權重，計算時再即時還原成 FP16。省記憶體與頻寬，對逐字生成最有效。GPTQ、AWQ、llama.cpp 的 GGUF 都屬此類。
  • W8A8：權重與啟動值（activation）都量化成 INT8 / FP8，可以直接使用整數或 FP8 Tensor Core 做矩陣乘法，對大批次、計算密集（compute-bound）的情境有幫助。 難點在於 LLM 的啟動值有固定幾個通道會出現巨大的離群值。
實驗 4：SmoothQuant —— 把啟動值的困難「搬」到權重上

CHAPTER 4

剪枝：刪掉不重要的連結

一句話重點 許多權重接近 0、對輸出貢獻很小，把它們設為 0（剪掉）就能減少儲存與計算。 兩個關鍵問題：剪哪些（重要性怎麼評估）與剪了之後硬體能不能真的加速（稀疏的形狀）。

三種稀疏形狀

  • 非結構化（Unstructured）：任何位置的權重都能剪。最有彈性、準確度損失最小，但零散的 0 很難讓 GPU 加速。
  • 結構化（Structured）：整個神經元、通道、注意力頭甚至整層一起剪。矩陣直接變小，任何硬體都能加速，但準確度損失較大。
  • 半結構化 N:M：每 M 個連續權重中保留 N 個，例如 2:4（固定 50% 稀疏）。NVIDIA Ampere 以後的 Sparse Tensor Core 原生支援。

最常見的重要性標準是權重大小（magnitude）：|w| 越小越不重要。更進階的方法會考慮啟動值（例：Wanda 用 |w|·‖x‖）或二階資訊（例：SparseGPT）。

知識蒸餾：讓大模型教小模型

一句話重點 先訓練一個大而準的老師模型，再讓一個小的學生模型去模仿老師輸出的機率分佈，而不只是學資料集的標準答案。 這些分佈裡藏著「類別之間有多像」的資訊，稱為暗知識（dark knowledge）。
輸入圖片🐱
→
老師（大模型）凍結，不訓練
→

資料集的硬標籤只說「這是貓」；但老師說「這 80% 是貓、15% 像老虎、幾乎不可能是汽車」。 學生因此學到「貓和老虎很像、和汽車完全不像」，這比單一答案提供了更多訊息，所以常常學得更快、泛化更好。

溫度（Temperature）讓分佈變軟

pi(T) = exp(zi / T)Σj exp(zj / T) z = logits（softmax 之前的分數）。T = 1 是一般的 softmax；T 越大，分佈越平滑，小機率類別之間的差異越明顯。
L = α · CE(y, ps) + (1 − α) · T² · KL( pt(T) ‖ ps(T) ) 第一項：學生學資料集的硬標籤；第二項：學生模仿老師的軟標籤。乘上 T² 是因為軟標籤項的梯度大小約與 1/T² 成正比，乘回來才能讓兩項的比重不隨 T 改變（Hinton 等人，2015）。
實驗 6：調整溫度，看見暗知識；再讓學生學習

老師的 logits

學生的 logits

「學一步」= 對學生 logits 做梯度下降：∂L/∂zs = α(ps − y) + (1−α)·T·(ps(T) − pt(T))。

🔍 動手觀察
  1. T = 1 時，老師幾乎把所有機率都給「貓」，看起來和硬標籤差不多；把 T 拉到 4–8，「老虎」「狗」的機率浮現出來，而「汽車」「飛機」仍然很低 —— 這就是暗知識。
  2. α = 1（只學硬標籤）時按「學 60 步」，學生只會把「貓」推高，其他類別的相對關係不會被學到；α = 0.3、T = 4 再試一次，學生的分佈會越來越像老師。
  3. T 太大（例如 20）時，所有類別都趨近 20%，資訊反而被稀釋。實務上 T 常在 2–10 之間。

蒸餾的變形與實例

  • 回應式蒸餾（如上）：模仿老師的輸出分佈。
  • 特徵式蒸餾：模仿老師中間層的特徵或注意力圖（例：FitNets、TinyBERT）。
  • LLM 蒸餾：用大模型產生的回答、推理過程（chain-of-thought）或每個 token 的機率分佈來訓練小模型。
  • 實例：DistilBERT 比 BERT-base 小 40%、快 60%，保留約 97% 的語言理解能力（Sanh 等人，2019）。
⚠️ 常見誤解 「蒸餾會把老師壓縮成學生」—— 蒸餾不會改動老師，它是一種訓練方法：學生的架構（多小、幾層）要自己設計， 而且需要訓練資料與運算資源。它常和剪枝搭配：先結構化剪枝得到小架構，再用原模型當老師蒸餾恢復能力。

CHAPTER 6

低秩分解：用兩個瘦矩陣取代一個胖矩陣

一句話重點 一個 m × n 的矩陣如果「資訊有很多重複」，就能近似成 (m × r) · (r × n) 兩個瘦矩陣的乘積， 參數從 m·n 降到 r·(m + n)。最佳的近似可以用 SVD（奇異值分解）求得。
A = U Σ Vᵀ = σ₁u₁v₁ᵀ + σ₂u₂v₂ᵀ + … 　→　Ar = Σk=1..r σk uk vkᵀ σ₁ ≥ σ₂ ≥ … ≥ 0 是奇異值，代表每個「成分」的重要程度。只保留前 r 個，就是 Frobenius 範數意義下最好的 rank-r 近似（Eckart–Young 定理）。 相對誤差 = √(Σk>r σk²) / √(Σ σk²)。

🔍 動手觀察
  1. r = 1：只剩一組 u·vᵀ，畫面變成「列向量 × 行向量」的格子狀 —— 這就是 rank-1 矩陣的樣子。
  2. r 從 1 拉到 16：圓形與大塊漸層很快就出現（低秩結構），但右下的斜條紋需要很多成分才清楚（高秩結構）。
  3. 看奇異值曲線：衰減得越快，代表越適合低秩壓縮。

應用到神經網路

全連接層 y = Wx，W 是 dout × din。分解成 W ≈ Ur·Vr 後，等於把一層拆成兩層： 先 Vrx（降到 r 維），再乘 Ur。參數與計算量都從 dout·din 降到 r·(dout + din)。

實驗 8：一層要分解到多小才划算？

LoRA：低秩的另一種用法

LoRA（Hu 等人，2021）不是用來壓縮原模型，而是讓微調變便宜：凍結原本的 W，只學一個低秩的修正量。

W′ = W + ΔW = W + B·A，　B ∈ ℝd×r，A ∈ ℝr×k，r ≪ d 4096 × 4096 的層、r = 8：只需訓練 8 × (4096 + 4096) = 65,536 個參數，是原本 1677 萬的 0.39%（上面計算器的預設值就是這個例子）。 QLoRA 更進一步把凍結的 W 量化成 4-bit（NF4），讓單張消費級 GPU 也能微調數百億參數的模型。
⚠️ 常見誤解 「所有權重矩陣都像照片一樣低秩」—— 訓練好的神經網路權重，奇異值往往衰減得沒那麼快，直接截斷常會明顯掉準確度， 通常需要搭配微調或蒸餾。低秩分解在嵌入層、注意力投影層等特定層效果較好。

經典的 Deep Compression（Han 等人，2016）就是「剪枝 → 量化 → 霍夫曼編碼」三段式，把 AlexNet、VGG-16 壓縮了 35–49 倍而不損失準確度。

📌 全課程回顧
  • 大小 = 參數數 × 位元數；LLM 逐字生成受限於頻寬，所以壓縮直接帶來加速。
  • 量化：x̂ = s(q − z)；位元越少誤差越大，離群值是大敵，用細粒度、截斷、SmoothQuant / AWQ 等方法對付。
  • 剪枝：剪小權重；非結構化最準，結構化 / N:M 才好加速；剪完要微調。
  • 蒸餾：學生模仿老師的軟標籤，溫度 T 讓暗知識浮現。
  • 低秩：SVD 截斷是最佳低秩近似；r < mn/(m+n) 才划算；LoRA 是低秩用於微調。
  • 壓縮會帶來誤差，重新訓練（微調、QAT、蒸餾）是讓模型適應誤差的通用解法。

Rank（秩）
矩陣中線性獨立的列（行）數量，可理解為「真正的資訊維度」。
Memory-bound
效能受限於資料搬運速度而非計算速度的狀態。
✏️ 期末綜合測驗

1. 你想在 8 GB 顯示卡上執行一個 13B 參數的 LLM，最直接可行的做法是？

  1. 使用 FP16
  2. 2:4 剪枝
  3. LoRA 微調
  4. 4-bit 權重量化（約 6.5–7 GB）
13×10⁹ × 4 bits ≈ 6.5 GB（加上 scale 略多），勉強放得下；FP16 要 26 GB。2:4 剪枝在一般格式下最多省一半，而且需要特定支援；LoRA 不會讓模型變小。

2. 下列哪一個敘述是錯誤的？

  1. 非結構化剪枝 50% 一定會讓 GPU 推論快 2 倍
  2. 對稱量化的 zero-point 為 0
  3. 知識蒸餾需要訓練學生模型
  4. rank-r 分解在 r 太大時參數會比原本還多
非結構化稀疏需要專門的格式與 kernel，一般稠密運算不會跳過 0，通常無法直接加速。

3. 為什麼 4-bit LLM 量化大多採用 per-group（例如 g = 128）而不是 per-tensor？

  1. per-tensor 不能在 GPU 上執行
  2. per-group 檔案比較小
  3. 每組有自己的 scale，能把離群值的影響侷限在小範圍，大幅降低誤差
  4. per-group 不需要 scale
4-bit 只有 15 個刻度，對範圍非常敏感；分組後每組各自決定範圍，代價是平均多約 0.125 bit。
